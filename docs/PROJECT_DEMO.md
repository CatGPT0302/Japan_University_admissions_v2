# admissions_v2：个人项目展示

## 一句话定义

一个利用 AI 整理日本大学招生 PDF 的个人项目：把分散在文件中的报考条件变成有原文依据、可人工复核、可继续使用的数据。

## 为谁解决什么问题

准备申请的同学需要反复翻阅不同大学的募集要项，比较申请时间、EJU 科目、英语条件和选考方式。文件中的跨页表格、日期例外和学科差异容易被遗漏。这个项目先整理信息，再把不确定的地方交给人核实，不替使用者做最终报考资格判断。

## 工作流程

```text
公开招生 PDF 放入本地文件夹
              |
              v
Codex 直接阅读，记录字段和原文页码
              |
              v
结构化 JSON + 文件指纹校验
              |
              v
待复核资料：显示条件、证据和疑点
              |
              v
人核对原文、修改、明确完成复审
              |
              v
确认数据 -> 查询 / 阅读报告 / 可选表格导出
```

这是目标流程，不表示每个环节均已验收。当前证据见 `DEMO_BROWSER_CHECK.md`；真实用户反馈见 `USER_TRIAL.md`，尚未开展的项目必须保留空白。

## 三分钟演示稿

### 0:00–0:30：问题

“同学看招生 PDF 时，真正想知道的是要考哪些科目、什么时候申请，而不是自己再整理一遍几十页文件。我做了一个辅助整理工具，让这些信息变得容易比较，也保留核实依据。”

### 0:30–1:10：输入与结果

打开福井大学原始 PDF，再打开五个学科的待复核结果。指出实际招生年度为2027，但申请在2026年。说明这份数据由 Codex 阅读产生，没有另外调用模型 API，也没有把 AI 输出当作最终答案。

### 1:10–1:50：展示一个关键细节

切到考试要求，打开 PDF 第15页。说明“理科三选二”和“数学课程2”必须完整保留。再查看申请与入学手续的截止规则，指出前者的邮寄消印例外不能复制到后者。

### 1:50–2:30：展示边界和纠错

指出 TOEFL 有效期在 PDF 第10页与第12页矛盾，不能猜一个日期。演示修改草稿并重新打开，说明“保存”不等于“已复审”，未解决的问题继续保留。确认和导出部分只有在真实人工核对完成后才演示；否则明确说明仍待验收，不临时伪造确认记录。

### 2:30–3:00：自己的工作与下一步

“我负责定义用户问题、字段规则、工作流程和验收标准，利用 Codex 辅助实现代码。浏览器试跑发现资格与材料在接口中被漏掉，以及保存会丢失部分证据，我补了测试和修复。下一步让同学试用，再根据真实反馈改进。”

## 如何介绍技术参与

可以说：用 Python/FastAPI、React/TypeScript 和本地数据库实现资料整理与复核；用结构化数据连接抽取和展示；用测试与浏览器检查验证结果。

不要说：独立手写全部代码、已达到生产级 SaaS、已证明节省某个百分比的时间，或已有用户认可。只有测量和记录支持的结论才能放进介绍。

这个项目要展示的不是“技术名词多”，而是能提出具体需求、做出可用流程、发现问题并验证修复。
