# 本地文件夹批量演示

## 最简单的使用方式

把公开PDF放在一个文件夹，告诉Codex：

> 直接阅读这个文件夹中的日本大学招生PDF，不另外调用模型API。按项目现有示例逐份整理JSON，保留EJU选科、分数、日期例外、页码和原文勘误。不能确定的内容列为待复核，然后用批量入口生成可读数据包。

Codex需要先实际读取文件。下面的Python命令只处理已经读出的结果，不会把未读PDF自动变成正确数据。独立skill已构建、安装并出现在本机Codex可用技能列表中，安装版打包入口也已运行验证。分享方法见 `SKILL_SHARING.md`；另一位真实用户的使用验证仍待完成。

## 输入

- 一个平铺的PDF文件夹，不扫描子文件夹。
- 一个抽取JSON文件夹，一份文档一个文件，结构见 `examples/demo/`。
- 每个JSON必须带源PDF的SHA-256与字段页码；同一个PDF不能有多个相互竞争的JSON。
- 同内容重复PDF按指纹去重。任一PDF缺抽取结果或校验失败，整批先停止，不生成看似完整的报告。

## 命令

在仓库根目录运行：

```bash
.venv/bin/python -m scripts.demo_batch runtime/local_demo/batch_inputs --extractions examples/demo --output runtime/local_demo/batch_result
```

`batch_inputs` 中的两份PDF是现有公开文件的演示副本。`batch_result` 已用于本次验收，再次运行请指定新的输出目录；工具拒绝覆盖已有报告。

加 `--import-staging` 可逐文档导入隔离演示库。导入不会确认记录，已有相同数据包不会重复新增；同一PDF改变了抽取内容后属于新版本，应检查重复版本，不能假设自动合并。

## 看哪个文件

| 文件 | 用途 |
| --- | --- |
| records_readable.md | 先看这个：按大学和课程展示条件、页码、待复核问题 |
| records.jsonl | 完整结构化草稿，每行一条，保留来源、字段证据与待复核状态 |
| records_table.csv | 表格阅读；可能触发公式的文本加前导单引号，原值仍在JSONL |
| review_queue.json | 每个关键字段的当前值、页码、引用与复核问题 |
| validation_report.json | 文档数、记录数和结构校验状态；不证明事实正确 |
| import_status.json | 仅使用导入选项时生成，记录逐文档导入是否成功 |

这个包是抽取JSON的快照，不是数据库中后续人工修改的实时镜像。不要把旧报告当成最新已确认结果。人工保存与确认仍在工作台进行。
